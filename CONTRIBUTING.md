# Как мы работаем

Вся работа идёт через GitHub: задача (Issue) → ветка → Pull Request → ревью → merge.

## Цикл задачи

1. Капитан создаёт Issue по шаблону и назначает исполнителя, метку и milestone.
2. Исполнитель создаёт ветку от свежего `main`:
   ```bash
   git switch main && git pull
   git switch -c feat/12-csv-loader
   ```
   Имена веток: `feat/<номер>-<кратко>`, `fix/<номер>-<кратко>`, `docs/<номер>-<кратко>`.
3. Работа небольшими коммитами с понятными сообщениями.
4. Pull Request в `main`, в описании `Closes #12`. PR небольшой (желательно до 300 строк).
5. Другой участник делает ревью в течение нескольких часов.
6. Merge через **Squash and merge**, ветку удаляем.

## Правила

- В `main` напрямую не пушим — только через Pull Request.
- Каждый отвечает за свою папку (`backend/`, `frontend/`, `db/`); в чужую — по согласованию.
- Общие файлы (`docker-compose.yml`, `README.md`) меняем через PR и сообщаем в чате команды.
- Перед началом работы всегда `git pull` в `main`.
- Ветка живёт дольше суток — подтягиваем `main` в неё (`git merge main`).
- **Не коммитим**: CSV-данные, пароли, ключи, файл `.env`. Для настроек есть `.env.example`.
- Ежедневный созвон 10 минут: что сделано, что мешает, что дальше.

## Метки

- Тип: `backend`, `frontend`, `data`, `llm`, `docs`, `bug`
- Приоритет: `P0` (блокирует), `P1`, `P2`
