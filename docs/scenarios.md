# Сценарии кейса

| № | Сценарий | Статус | Как реализовано |
|---|---|---|---|
| 1 | Первичное знакомство с данными | готово | «Опиши данные»: описание таблиц, полей, периода и качества по каталогу (`backend/llm/describe.py`) |
| 2 | Ответы на вопросы по содержанию | готово | выбор таблицы → SQL → проверка → выполнение только на чтение → ответ с таблицей, графиком и SQL (`backend/llm/ask.py`) |
| 3 | Группировки и аномалии | готово | группировки и уточнение единицы счёта; поиск дублей и аномалий в метриках (`advanced_analytics.py`) |
| 4 | Визуализация ответов | готово | график подбирается по результату, вид меняется кнопкой или командой; отдельные/общие графики, объединение и разбивка по признаку |
| 5 | Дашборд по запросу | готово | «Собери дашборд» и «+ На дашборд»; дашборды сохраняются на сервере, открываются по ссылке, фильтр периода, экспорт в PDF и Excel |
| 6 | Диалог с контекстом | готово | память по сессии: «а теперь только за сентябрь», «продли прогноз»; смена источника начинает новый контекст |
| 7 | Повторяющиеся закономерности | готово | сезонность и пики по месяцам (`advanced_analytics.py`) |
| 8 | Сегменты и отличия | готово | сравнение периодов и сегментов (`compare.py`), разбивка по признаку в интерфейсе |
| 9 | Корреляции и лаги | готово, требуется ручная API-приёмка | обычная корреляция (`advanced_analytics.py`); проверяемый поиск лагов ±N дней по двум явно названным числовым показателям одной таблицы (`lag_analysis.py`), реальные совпадения календарных дат, Pearson r и число пар, пропуски не интерполируются; сдвиги между несвязанными таблицами не заявляются |
| 10 | Экстраполяция и «что если» | готово | прогноз по тренду с горизонтом («следующий квартал», «на 6 месяцев»), сценарные расчёты (`whatif.py`) |

Проверка интерфейса на реальном API — [frontend-check.md](frontend-check.md).
Ограничения: на маленькой локальной модели сложные формулировки иногда требуют уточнения;
организаторы подключают более крупную открытую модель.
