# Архитектура: решения по PostgreSQL

Итоговое описание архитектуры — [Architecture.md](../Architecture.md).

## Выбранные технологии

- **БД: PostgreSQL 16.** Локальный экземпляр поднимается в Docker; на
  проверке приложение подключается к предоставленному PostgreSQL.
- **Backend:** Python + FastAPI; исследователь схемы и LLM-агент.
- **Frontend:** React + Vite, ECharts для графиков. Фронтенд не зависит
  от выбранной СУБД и общается с backend через `POST /api/chat`.
- **LLM:** OpenAI-совместимый endpoint, с возможностью замены на
  open-source модель организаторов менее 80B.

## Поток запроса

1. Пользователь задаёт вопрос в чате.
2. Backend исследует неизвестную схему PostgreSQL и получает метаданные
   из `information_schema` и статистики таблиц.
3. LLM формирует SQL **диалекта PostgreSQL**, опираясь на доступную схему.
4. Перед выполнением SQL проходит проверку: только безопасное чтение,
   лимиты результата, таймаут. Запрос выполняется под ролью только для чтения.
5. Backend проверяет результат, строит спецификацию графика при необходимости
   и возвращает ответ в формате `docs/api-contract.md`.
6. История диалога хранится по `session_id`.

## Данные

- Для разработки: предоставленные CSV импортируются в схему `raw` как есть.
  Все ячейки хранятся как `TEXT` (см. `db/README.md`).
- В `bi_meta.imports` находится справка по исходным заголовкам и файлам.
- Преобразование строк к числам, датам и другим типам выполняется после
  загрузки внутри платформы, с учётом формата значений.
- Нельзя предполагать фиксированные таблицы или заранее известные связи.

## Защита от ошибок слабой LLM

- Схема и значения полей предоставляются через отдельные инструменты;
  модель не должна угадывать несуществующие поля.
- SQL проверяется и выполняется с ограниченными правами.
- При SQL-ошибках возможно контролируемое повторное построение запроса.
- Сложные вопросы можно разбивать на шаги.
- Неоднозначные вопросы уточняются вместо выдуманного ответа.

## Профилирование схемы (модуль `db/profile_db.py`)

Отдельный read-only модуль позволяет определить структуру неизвестной
PostgreSQL-базы: таблицы/поля, семантические типы, формат чисел, пустые
значения, примерную кардинальность и примеры. Возвращает JSON, пригодный
для передачи backend/LLM. Анализ выборочный, гипотезы требуют проверки
на полном наборе перед выполнением числовых преобразований. Модуль
не исполняет SQL, который генерирует модель, и не является заменой
SQL-валидатора.

Случайная выборка для больших PostgreSQL-таблиц: TABLESAMPLE SYSTEM
по физическим блокам + перемешивание отобранных строк. Статистика
выборочная; название колонки без данных даёт только type_hint.
