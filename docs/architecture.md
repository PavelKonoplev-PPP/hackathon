# Архитектура (черновик)

## Решение
- **БД:** ClickHouse (быстрая аналитика на миллионах строк), подключение по настройкам из `.env`.
- **Бэкенд:** Python + FastAPI, внутри LLM-агент.
- **Фронтенд:** React: чат, графики, сохранённые дашборды.
- **LLM:** любой OpenAI-совместимый endpoint. На проверке организаторы подключат свою
  open-source модель (до 80B), поэтому решение не должно зависеть от сильной модели.

## Поток запроса
Вопрос → LLM строит SQL по схеме → проверка и выполнение в ClickHouse →
LLM выбирает визуализацию и пишет пояснение → ответ в чате.

## Что учитываем из-за слабой модели
- Схема и описания полей передаются агенту в готовом виде.
- SQL проверяется перед запуском; при ошибке агент исправляет запрос.
- Сложный вопрос разбивается на простые шаги.
- Непонятный или некорректный вопрос — уточнение или вежливый отказ.
