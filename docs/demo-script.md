# Сценарий демо (≈7 минут)

Цель — за 7 минут показать жюри все критерии кейса на живой системе: данные «как есть»,
ответы на естественном языке, графики, дашборды, работа с неудобными вопросами, локальный запуск.

## Перед показом (за 30 минут)

- [ ] Подняты PostgreSQL (9 CSV загружены), бэкенд и модель; во фронтенде `VITE_MOCK=0`, бейджа «Демо-режим» нет.
- [ ] `GET /api/health` → `"database": true`; в чате вопрос «Опиши данные» отвечает.
- [ ] Прогнаны все вопросы ниже; ответы сохранены (скриншоты) на случай сбоя модели.
- [ ] Подготовлен небольшой CSV для загрузки (10–100 строк, разделитель `;`, десятичная запятая).
- [ ] Браузер в полноэкранном режиме, светлая тема, масштаб 110–125 %.
- [ ] Запасной план: если модель не отвечает — переключиться на скриншоты или демо-режим (`VITE_MOCK=1`) и честно сказать об этом.

## Вопросы для показа

Команда LLM проверяла на реальных данных (qwen2.5:3b):
- «Какой канал продаж приносит больше всего выручки?»
- «Какая средняя оценка клиентов в техподдержке?»
- «Сколько потрачено на рекламу по площадкам?»

Ещё не проверены с моделью:
- «Опиши данные»
- «Покажи динамику продаж по месяцам»
- «А теперь только за сентябрь» (контекст диалога)

Перед показом прогоните все вопросы на той модели, которая будет на демо, и оставьте только те, что отвечают стабильно.

## Если что-то пошло не так

- **Модель долго думает** — показать этапы выполнения: это и есть прозрачность агента.
- **Ответ неверный** — открыть «Как посчитано» и показать, что SQL проверяется и выполняется только на чтение.
- **Ошибка подключения** — переключиться на заранее сохранённый дашборд: он хранит результаты и открывается без модели.
