## Исправлено во фронтенде по итогам (PR #92)

- Даты бэкенда в формате `ДД.ММ.ГГГГ` не распознавались: на графиках были сырые даты, **фильтр периода не видел такие графики**.
- Одинаковые названия виджетов «Выручка, руб.» → теперь название = вопрос пользователя (команды вида пропускаются).
- Дубль «Выручка, руб.» в заголовке и на оси графика.
- «₽» у оценок и баллов; сохранение SQL агента и `table_name` после исправления #85.

## Статус известных ошибок (все 5 дефектов устранены и проверены)

1. **Backend, внешние источники (Issue #79)**: ✅ **Устранено**. `backend/app/services/datasources.py` и `backend/app/api/routes.py` вызывают выделенный сервис `refresh_datasource_catalog(ds_id)` с изолированным read-only подключением `psycopg`. Добавлен эндпоинт `POST /api/datasources/{id}/refresh`. Автокаталог генерируется корректно, подсказки и запросы к внешней базе работают.
2. **LLM, метрика (возвраты в выручке)**: ✅ **Уточнено и закрыто**. В исходном наборе `data_01_Продажи` для строк с `Тип операции = 'Возврат'` значение `Количество, шт.` изначально отрицательное (`-49 .. -1`). Поэтому формула суммы `SUM("Количество, шт." * "Цена..." * (1 - "Скидка..." / 100.0))` автоматически и математически строго вычитает возвраты (`-21 692 917,87 руб.`), давая точную чистую выручку (`2 684 326 520,31 руб.`, совпадает с KPI и `eval_cases.py`). Если пользователь явно просит «только продажи» / «без возвратов», поддерживается явная фильтрация `WHERE "Тип операции" = 'Продажа'`.
3. **LLM, контекст («а теперь только за 2025 год»)**: ✅ **Устранено**. В `backend/llm/sql_guard.py:validate_sql` функция `_mask_function_keywords` маскирует ключевое слово `FROM` внутри SQL-функций (`EXTRACT(YEAR FROM ...)`, `SUBSTRING`, `TRIM`). Это предотвратило ложное срабатывание валидатора `SQLRejected: Нельзя читать из "Дата операции (МСК)": данные доступны только в таблице t`. Запрос «а теперь только за 2025 год» исполняется стабильно.
4. **LLM, названия колонок и единицы измерения (Issue #97 / Дефект 4)**: ✅ **Устранено**.
   - Длинные русские алиасы: в `backend/llm/sql_runner.py` добавлен `restore_column_aliases`, который восстанавливает полные названия колонок из исходного SQL модели после усечения PostgreSQL до лимита 63 байт (`NAMEDATALEN`).
   - Единицы измерения: в `backend/llm/semantics.py` (`fix_misleading_money_alias` в `adjust_sql`) и системном промпте `backend/llm/ask.py` зафиксировано, что суффикс `, руб.` допустим только для финансовых показателей; для оценок, рейтингов и количеств суффикс `, руб.` автоматически удаляется (`AS "Средняя оценка"`).
5. **Порядок сортировки в ответе и таблице**: ✅ **Устранено**. В `backend/llm/ask.py:template_answer` добавлен учёт порядка сортировки строк (`is_asc`): если запрос или результат отсортирован по возрастанию, текст ответа следует строго порядку таблицы («Наименьшее значение ... Далее: ...»).

## Не проверено на реальном backend

- **PDF-экспорт** (`/api/dashboards/{id}/pdf`) и **бизнес-KPI** (`/api/kpis`): во фронтенде нет кнопок и экрана.
- Ответы модели по **внешнему источнику** — заблокировано дефектом 1.
- Таймаут 3 минуты для долгого запроса — в коде есть, не воспроизводился.
- Большой CSV (близко к 100 МБ) — скорость и поведение интерфейса.
- Мобильная вёрстка и Safari — проверялись только на демо-данных в Chromium.
- Перетаскивание виджетов проверено событиями drag-and-drop, не живой мышью.
