## Исправлено во фронтенде по итогам (PR #92)

- Даты бэкенда в формате `ДД.ММ.ГГГГ` не распознавались: на графиках были сырые даты, **фильтр периода не видел такие графики**.
- Одинаковые названия виджетов «Выручка, руб.» → теперь название = вопрос пользователя (команды вида пропускаются).
- Дубль «Выручка, руб.» в заголовке и на оси графика.
- «₽» у оценок и баллов; сохранение SQL агента и `table_name` после исправления #85.

## Известные ошибки (не фронтенд)

1. **Backend, блокирует внешние источники.** При подключении PostgreSQL падает автокаталог:
   `Catalog auto-refresh failed: 'PosixPath' object has no attribute 'execute'` —
   `backend/app/services/datasources.py:574` вызывает `refresh_catalog(Path('data'))` вместо подключения.
   Каталога у источника нет → на любой вопрос «Не получилось надёжно посчитать», а подсказки — про основную базу.
2. **LLM, метрика.** «Выручка» = количество × цена × (1 − скидка), но **возвраты не исключены** (`Тип операции = 'Возврат'`). Нужно решение: вычитать возвраты или считать только продажи.
3. **LLM, контекст.** «а теперь только за 2025 год» после графика по месяцам → «Не получилось надёжно посчитать»; «только за сентябрь 2025» — работает.
4. **LLM, названия колонок.** Длинные русские алиасы обрезаются PostgreSQL (63 байта): «Количество продаж без карты лояль». Оценка подписана «…, руб.» (на фронтенде «₽» уже не ставится).
5. **Мелочь.** Таблица результата бывает отсортирована по возрастанию, а текст ответа — по убыванию.

## Не проверено на реальном backend

- **PDF-экспорт** (`/api/dashboards/{id}/pdf`) и **бизнес-KPI** (`/api/kpis`): во фронтенде нет кнопок и экрана.
- Ответы модели по **внешнему источнику** — заблокировано дефектом 1.
- Таймаут 3 минуты для долгого запроса — в коде есть, не воспроизводился.
- Большой CSV (близко к 100 МБ) — скорость и поведение интерфейса.
- Мобильная вёрстка и Safari — проверялись только на демо-данных в Chromium.
- Перетаскивание виджетов проверено событиями drag-and-drop, не живой мышью.
