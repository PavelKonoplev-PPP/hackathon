# Сценарии и технические критерии

Статус: ✅ — выполнено, ◐ — выполнено частично.
Проверка: локальный стенд, PostgreSQL 16 с данными кейса (9 таблиц, 5,4 млн строк),
модель `qwen2.5:3b` через Ollama. Прогоны вопросов экспертов — [TestCases.md](TestCases.md).

## Сценарии кейса

| № | Сценарий | Статус | Как реализовано | Пример вопроса |
|---|---|---|---|---|
| 1 | Первичное знакомство с данными | ✅ | описание таблиц, полей, периода, объёма и качества по автоматическому каталогу; факты считает код, модель пересказывает | «Что есть в этих данных?» |
| 2 | Ответы на вопросы по содержанию | ✅ | выбор таблицы кодом → SQL → две проверки → выполнение только на чтение → ответ с таблицей, графиком и SQL; связи по идентификаторам из каталога связей | «Какие значения встречаются чаще всего в поле „Канал продажи“?» |
| 3 | Группировки и аномалии | ✅ | группировки с уточнением единицы счёта (строки или уникальные заказы), поиск дублей и выбросов | «Есть ли тут повторяющиеся данные?» |
| 4 | Визуализация | ✅ | график выбирается по форме результата; вид меняется кнопкой или фразой («покажи кругом»); несколько метрик — на одном или отдельных графиках | «Покажи наглядно, как распределена выручка по каналам» |
| 5 | Дашборд по запросу | ✅ | «Собери дашборд» из ответов диалога или «+ На дашборд» у любого ответа; виджеты перемещаются и меняют размер, общий фильтр периода, PDF и Excel | «Создай дашборд с ежеквартальной статистикой продаж» |
| 6 | Диалог с контекстом | ✅ | контекст по сессии: «то же самое в другом виде», «а теперь только за сентябрь», ответ на уточнение продолжает вопрос | «А теперь покажи то же самое линией» |
| 7 | Закономерности во времени | ✅ | сезонность и пики по месяцам, повтор через 12 месяцев | «Есть ли сезонные пики зимой?» |
| 8 | Сегменты и отличия | ✅ | группировка по комбинации признаков, сравнение сегментов и периодов, разбивка графика по признаку | «Чем отличаются способы доставки по сроку и стоимости?» |
| 9 | Корреляции и лаги | ✅ | корреляция Пирсона и временные сдвиги между показателями | «Есть ли связь между расходами на рекламу и числом кликов, с каким лагом?» |
| 10 | Экстраполяция и «что если» | ✅ | прогноз по тренду с горизонтом в кварталах или месяцах, сценарные расчёты при изменении параметра | «Какой рост выручки ожидается в следующем квартале?» |

## Технические критерии

| № | Критерий | Статус | Как выполнено |
|---|---|---|---|
| 1 | Прямое подключение к PostgreSQL или ClickHouse без предобработки | ◐ | PostgreSQL: раздел «Данные» → «Подключить базу», проверка соединения, автоматический каталог, работа только на чтение. ClickHouse не подключали |
| 2 | Сырые CSV в произвольном виде, обработка внутри платформы | ✅ | загрузка CSV в интерфейсе: предпросмотр, автоопределение разделителя и кодировки, до 100 МБ, защита от перезаписи. Данные хранятся как текст, типы определяет каталог, приведение — в запросе |
| 3 | Описание неизвестных данных простым языком и ответы по содержанию | ✅ | сценарии 1–2; ничего не зашито под таблицы кейса, каталог строится для любой базы |
| 4 | Визуализация в диалоге, вид подбирается и меняется по просьбе | ✅ | гистограмма, линия, круговая, таблица, KPI-карточки; смена вида кнопкой или фразой, объединение и разбивка графиков |
| 5 | Дашборд генерируется автоматически и доступен повторно | ✅ | дашборды хранятся на сервере, открываются из боковой панели, раздела «Дашборды» и по ссылке |
| 6 | Ответы понятны бизнес-пользователю | ✅ | ответ начинается с вывода, числа с разделителями и единицами (₽, %, шт.), месяцы словами, SQL и этапы скрыты под кнопкой |
| 7 | Память на уровне диалога | ✅ | контекст по `session_id`, история диалогов в интерфейсе, смена источника начинает новый контекст |
| 8 | Помощь с некорректными и «неудобными» вопросами | ✅ | уточнение кнопками при неоднозначности, подсказки при вопросах вне данных, отказ на изменение данных и опасные запросы |
| 9 | Локальный запуск без закрытых систем | ✅ | PostgreSQL, Ollama, FastAPI и интерфейс запускаются на одной машине, инструкция — [README.md](README.md) |
| 10 | Без облачных решений, только open source | ✅ | PostgreSQL, Ollama, Qwen 2.5 (Apache 2.0), FastAPI, React, ECharts — открытые лицензии |
| 11 | Интернет только к определённым доменам, без поисковиков | ✅ | платформа не обращается в интернет; модель и база локальные. Сеть нужна только для установки зависимостей и скачивания данных кейса |

## Результаты проверок

Точность агента — сквозной прогон через API (`python -m backend.llm.eval --api http://localhost:8000`),
модель `qwen2.5:3b`, 31.10.2026. Ответ засчитывается, если число или результат SQL совпадает с эталоном,
а уточнения и отказы даны там, где они нужны.

| Набор | Вопросов | Верно | Время ответа |
|---|---|---|---|
| Основной: факты, группировки, сравнения, «что если», диалоги, уточнения, отказы | 56 | 52 (93%) | медиана 3,1 с, 90% быстрее 5,6 с (оба набора) |
| Незнакомые вопросы, не использовались при настройке | 15 | 15 (100%) | |

Ошибки основного набора (4):
- два контрольных вопроса про покупки без карты лояльности: модель добавила в SQL лишнее
  условие и получила неверное число (SQL виден пользователю под ответом);
- один вопрос — уточнение единицы счёта там, где эталон ждал число;
- один диалог — агент не нашёл надёжного SQL и честно не показал цифры.

| Проверка | Результат | Команда |
|---|---|---|
| Тесты backend и агента | 256 пройдено | `python -m pytest -q backend` |
| Тесты загрузки и каталога | 110 пройдено | `python -m unittest discover -s db -p 'test_*.py'` |
| Контрольные расчёты на данных кейса | 25 из 25 | `python db/run_golden_checks.py` |
| Сборка интерфейса | без ошибок | `cd frontend && npm run build` |

## Известные ограничения

- Модель 3B на сложных формулировках иногда просит уточнение там, где крупная модель
  ответила бы сразу. С моделью организаторов (до 80B) это должно уйти.
- ClickHouse не подключён: подключение сделано только для PostgreSQL.
- Контекст диалога хранится в памяти backend и сбрасывается при его перезапуске;
  дашборды и сохранённые запросы сохраняются.
